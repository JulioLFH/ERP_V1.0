➜MIGRACIÓN
PROPUESTA

Servidor VPS propio: Django + PostgreSQL

Todo en un servidor Linux que ustedes administran: siempre encendido, con respaldos y dominio propio.

👥 Usuarios y sistemas

Mismos navegadores, tablets y API v1 · dominio propio, ej. erp.suempresa.pe (DNS → IP del VPS)

▼ HTTPS 443 (certificado Let's Encrypt, renovación automática)

🖥️ VPS Linux · Ubuntu 24.04 LTS (ej. 4 vCPU · 8 GB RAM · 160 GB SSD)

🛡️ Seguridad del servidor

Firewall UFW: abiertos solo 80/443; SSH (22) solo con llave y desde IP de administración · Fail2ban · actualizaciones automáticas

Nginx (servidor web)

Recibe HTTPS · sirve /static directo · reenvía el resto a Gunicorn · límite de archivos subidos · cabeceras de seguridad

Gunicorn (servicio systemd, 2×CPU+1 procesos) → Django · Ceiba ERP

El mismo código de GitHub · configuración en .env: SECRET_KEY, DATABASE_URL, DEBUG=0, ALLOWED_HOSTS · se reinicia solo si falla

🗄️ PostgreSQL 16 (en el mismo VPS, solo escucha en 127.0.0.1)

Base erp (empresa principal) + erp_empresa2 … una base por empresa · sin límite de 1 GB (el disco del VPS) · usuario propio con contraseña fuerte

⏱️ Tareas programadas (cron / systemd timers)

Respaldo diario pg_dump comprimido · limpieza de sesiones · aviso si el disco pasa el 80 %

🐙 GitHub → despliegue

desplegar.bat sube a GitHub y el VPS ejecuta deploy.sh: git pull · pip install · migrate · collectstatic · reinicia Gunicorn (por SSH o GitHub Actions).

💾 Respaldos fuera del servidor

  • pg_dump diario → almacenamiento externo (S3, Backblaze o Google Drive), 30 días
  • Instantánea semanal del VPS en el proveedor
  • Prueba de restauración mensual

🚚 Paso único de migración

cliente.sqlite3 (laptop) → trasladar_migracion → PostgreSQL del VPS · se valida contra Odoo · la laptop queda solo para desarrollo y pruebas
